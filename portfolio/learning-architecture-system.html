Learning architecture · Mical Neill

A completed course is not the same as a completed job.

Start with what someone needs to do. Give them something useful to make. Assess whether it works.

One job, one useful artifact.

Define the job

For example: hand a workflow to a colleague who has never run it. Name the inputs, the output and who checks it.

Make the handover

Write the steps, show one worked example and explain what to do when a check fails.

Test the result

Can the colleague complete the task without the original expert? The artifact is the evidence.

“Teach me” and “help me now.”

People need a learning path when the task is new. During the work, they may only need a reference card. Both should draw on the same maintained knowledge.

Adaptive paths and coaching

Measure what happens after the lesson.

Did the person complete the job? Could they explain the result? Did they know when to ask for help? Those are evaluation questions, not claims of measured improvement.

For a partner delivering software to customers, a usable handover is part of the offer. Start with the job your team needs to explain or support repeatedly.
